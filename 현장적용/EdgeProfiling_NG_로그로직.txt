WISVision IM — Edge Profiling NG
Unload / Manual Remove / Retry 로그 로직

작성: 2026-09-08
대상: 현장 WISVision IM 유닛 Visual Studio 프로젝트
이 GitHub(KGC_Coffee) 에는 IM 전체 소스가 없다.
아래에 적은 호출 이름은 현장 소스에서 그대로 있을 수도 있고
검색용 별칭일 수도 있다. 버튼 3개 분기 자체는 현장 코드에 있다.


============================================================
0. 한 줄 결론
============================================================

Edge Profiling NG 가 나면 알람 팝업과 함께
Unload / Manual Remove / Retry 모달 창이 뜬다.

Unload
  로컬 Inspect/Alarm 로그를 남기고
  상위(Parent / Host / CIM) 로 IM Inspection Error 를 올린다.
  그 다음 로봇 언로드.

Manual Remove
  로컬 로그만 남기고, IM Inspection Error 는 보통 올리지 않는다.
  로봇 언로드 없이 작업자가 웨이퍼를 직접 뺀다.
  웨이퍼 트래킹을 비운 뒤 다음 장을 기다린다.

Retry
  로컬 로그에 Retry Count 를 남기고
  IM Inspection Error 없이 같은 웨이퍼로 Edge Profiling 을 다시 탄다.

키보드 F3=Manual, R=Retry 는 AOI 단축키 로그이다.
NG 복구 팝업 버튼과 다른 경로다.


============================================================
1. 두 개의 Manual / Retry 를 섞지 말 것
============================================================

A) Edge Profiling NG 복구 팝업  ← 지금 보는 것
   버튼: Unload, Manual Remove, Retry
   시점: 엣지 프로파일링 판정 NG 직후
   로그: Inspect / Alarm / (Unload 만) 상위 IM Inspection Error

B) AOI 단축키  (이 repo 의 clsAOIKeys)
   Manual=F3, Retry=R
   시점: AOI 판정 화면에서 키를 누를 때
   로그: C:\WISVision\Log\AOIKeys_LAST.txt
         한 줄 예: Action=Retry Key=R
   이 파일은 NG 팝업 버튼 기록이 아니다.


============================================================
2. NG 발생부터 팝업까지
============================================================

자동 시퀀스 안에서 Edge Profiling 단계가 NG 가 되면
대략 아래 순서로 막힌다. (현장 함수명은 검색으로 확인)

  1. Edge Profiling 결과 NG
  2. clsLog.WriteLog("Inspect", "EdgeProfiling NG ...")
     또는 LotBoundary / FindEdge 이름 로그
  3. 알람 팝업 (Alarm)
  4. 복구 팝업 ShowDialog
       [ Unload ]  [ Manual Remove ]  [ Retry ]
  5. 작업자 입력을 기다린다. 자동 시퀀스는 여기서 정지.

Unload 를 누르면 상위 IM Inspection Error 가 뜬다.
이 동작은 확인된 사실이다.


============================================================
3. 버튼별 로그 / 상위보고
============================================================

--- Unload -------------------------------------------------

로컬
  clsLog.WriteLog("Inspect", "EdgeProfiling NG Operator=Unload");
  clsLog.WriteLog("Alarm",   "IM Inspection Error");

상위
  Parent / Host / CIM(SECS) 로 IM Inspection Error 보고
  웨이퍼는 NG 언로드 (카세트/포트로 로봇 반출)

이후
  해당 슬롯 결과 NG 로 닫고 다음 웨이퍼 또는 설비 정지
  (레시피/호스트 설정에 따름)


--- Manual Remove ------------------------------------------

로컬
  clsLog.WriteLog("Inspect", "EdgeProfiling NG Operator=ManualRemove");
  확인 창이 있으면
  clsLog.WriteLog("Inspect", "ManualRemove Confirmed");

상위
  IM Inspection Error 는 보통 안 올린다.
  (Unload 와 달리 로봇 반출이 없고, 작업자가 직접 제거)
  사이트에 따라 Wafer Removed / Abort / Skip 같은
  다른 이벤트를 올릴 수는 있다.
  그 경우에도 알람 텍스트는 Inspection Error 가 아니다.

이후
  스테이지 웨이퍼 정보 클리어
  다음 장 투입 대기 또는 로트 스킵
  카세트 슬롯은 장비가 언로드하지 않았으므로
  호스트 맵과 실물이 어긋날 수 있다. 그래서 로컬 로그가 중요하다.


--- Retry --------------------------------------------------

로컬
  clsLog.WriteLog("Inspect",
      "EdgeProfiling NG Operator=Retry Count=" + nRetry);

상위
  IM Inspection Error 없음. 팝업만 닫는다.

이후
  같은 웨이퍼, 같은 슬롯으로 Edge Profiling 재진입
  (재촬상 → 엣지 검출 → 프로파일 판정)
  다시 NG 이면 같은 팝업이 또 뜬다.
  재시도 횟수 제한이 있으면 초과 시 Unload 강제 또는 팝업 재표시.

4. 로그가 남는 파일 (현장 PC)
============================================================

공통 (기존 WISVision clsLog 자리)

  C:\WISVision\Log\Inspect_LAST.txt
  C:\WISVision\Log\Alarm_LAST.txt
  C:\WISVision\Log\System_LAST.txt
  C:\WISVision\Log\LotBoundary_LAST.txt

  C:\WISVision\Log\{날짜}\Inspect_{날짜}.txt
  C:\WISVision\Log\{날짜}\Alarm_{날짜}.txt

Unload 한 직후 LAST 에서 볼 것
  EdgeProfiling NG
  Operator=Unload
  IM Inspection Error

Manual Remove 한 직후 LAST 에서 볼 것
  EdgeProfiling NG
  Operator=ManualRemove
  (IM Inspection Error 줄이 따라오는지 여부 ← 확인 포인트)

Retry 한 직후 LAST 에서 볼 것
  Operator=Retry Count=N
  바로 뒤에 EdgeProfiling 시작/재시도 줄
  (IM Inspection Error 없음이 정상)

AOIKeys_LAST.txt 에 Action=Retry / Action=Manual 만 있고
Inspect_LAST 에 Operator= 가 없으면
복구 팝업 쪽 WriteLog 가 아직 없거나 다른 모듈명을 쓰는 것이다.

============================================================
7. 현장 확인 순서
============================================================

1) VS 에서 "Manual Remove" 검색 → 복구 팝업 폼/분기 파일 연다.
2) Unload 분기에 IM Inspection Error / SetAlarm 가 있는지 확인.
3) Manual Remove / Retry 분기에 WriteLog 가 있는지 확인.
4) 설비에서 Edge Profiling 을 NG 로 재현한다.
5) Unload 한 번, LAST 저장 복사.
6) Manual Remove 한 번, LAST 저장 복사.
7) Retry 한 번, LAST 저장 복사.
8) 세 파일이 이 메모 3번과 같은지 비교한다.

Manual Remove / Retry 에 WriteLog 가 없으면
로그가 안 남는 것이 버그가 아니라 원래 호출이 없는 것이다.
그때는 EdgeProfilingNgRecovery.cs 의 OnOperatorChoice 를
해당 버튼 핸들러에 넣으면 Inspect_LAST 에 남는다.
끝.
